## EXECUTIVE_SUMMARY

The recommended factuality layer is **claim-centric, source-first and hybrid**. It should not ask a model for a single “factuality score”. It should instead preserve source provenance, decompose generated text into atomic material claims, extract high-risk deterministic anchors, retrieve candidate evidence, run deterministic mismatch checks before semantic verification, and expose claim-to-source lineage in the UI.

Core invariant:

```text
SOURCE PDF/TEXT
→ provenance-preserving extraction
→ SourceSpan / TableCell ledger
→ output generation
→ atomic Claim extraction
→ deterministic Anchor checks
→ candidate evidence retrieval
→ semantic entailment / contradiction / alignment
→ severity + hard-gate policy
→ targeted repair / human review when needed
→ claim-level source lineage UX
```

For financial content, **deterministic contradictions have veto power over semantic scores**. A semantic model must never “average away” a wrong number, wrong unit, wrong entity, inverted direction, negation loss, conditional-to-fact promotion, or wrong financial metric. Conversely, exact string equality is insufficient: the same number can refer to a different metric, entity, period or table cell. The evaluator therefore needs both symbolic anchors **and** semantic role/support checks.

The proposal directly addresses `REQ-001`, `REQ-012`, `REQ-016`, `REQ-018`, `PAIN-002`, `PAIN-004`, `RISK-0001`, `RISK-0010`, and `CRIT-001` without relying on LLM consensus as truth.

# FINDINGS / EVIDENCE

## 1. Why atomic claims are the right evaluation unit

**Evidence.** FActScore (EMNLP 2023) evaluates long-form generations by breaking text into atomic facts and checking what fraction is supported by a reliable source. This is materially better aligned with the case than binary whole-document “factual / non-factual” labels because one generated paragraph can contain several supported facts plus one critical hallucination.

Source: https://aclanthology.org/2023.emnlp-main.741/

**Design consequence.** Every generated output must be decomposed into verifiable material claims before factuality evaluation. Compound sentences can yield multiple claims. Claim extraction may use a structured model as a parser, but support/contradiction truth must come from source evidence plus deterministic/semantic checks, not from the parser’s opinion.

## 2. NLI works better when granularity matches the task

**Evidence.** SummaC (TACL 2022) showed that sentence/document granularity mismatch harmed prior NLI factuality checks; sentence-level segmentation plus aggregation improved inconsistency detection. The paper reports 74.4% balanced accuracy on its benchmark, 5 percentage points above prior work in that setup.

Source: https://aclanthology.org/2022.tacl-1.10/

**Design consequence.** Do not compare an entire long PDF with an entire output in one NLI call. Retrieve a compact evidence packet per atomic claim, preserving nearby context and table headers, then evaluate the claim against that packet.

## 3. QA and entailment are complementary sensors

**Evidence.** QAFactEval (NAACL 2022) found that careful QA design—especially question generation and answerability classification—substantially improved factual consistency evaluation and that QA-style and entailment-style signals can complement each other.

Source: https://aclanthology.org/2022.naacl-main.187/

**Design consequence.** NLI/alignment should be the default semantic support layer; a QA probe can be a secondary escalation path for ambiguous or high-risk claims. It should not be run blindly on every claim if latency/cost is not justified.

## 4. Unified semantic alignment is useful, but not a substitute for anchors

**Evidence.** AlignScore (ACL 2023) trains a general alignment function over diverse tasks including NLI, QA, fact verification, retrieval, semantic similarity and summarization, demonstrating that semantic factuality benefits from multiple supervision types rather than a single brittle formulation.

Source: https://aclanthology.org/2023.acl-long.634/

**Design consequence.** The semantic verifier can be implemented by NLI/alignment-family models and calibrated on the project gold set, but it remains one sensor. It cannot override deterministic critical anchor mismatches.

## 5. Small dedicated fact-checkers are credible candidates for the semantic layer

**Evidence.** MiniCheck (EMNLP 2024) trains compact grounding fact-checkers on structured synthetic error cases and reports GPT-4-level accuracy on its benchmark at far lower inference cost. Its core task—checking a claim against grounding documents—matches the proposed claim/evidence interface well.

Source: https://aclanthology.org/2024.emnlp-main.499/

**Design consequence.** Candidate semantic backends for later implementation should include a dedicated grounding verifier such as MiniCheck-family models alongside generic NLI/alignment baselines. The project must benchmark locally on financial examples rather than inherit paper claims as project truth.

## 6. Financial-domain evidence supports an NLI layer, but calibration remains mandatory

**Evidence.** FinNLP 2025 published work using Natural Language Inference as a judge for factuality and causality issues in financial analysis. This is domain-relevant evidence that entailment/contradiction is useful in finance-specific evaluation.

Source: https://aclanthology.org/2025.finnlp-2.14/

**Design consequence.** NLI belongs in the architecture, but thresholds and error expectations must be calibrated on the W001-T005 financial golden/held-out dataset. No universal confidence cutoff is proposed here.

## 7. Project evidence strongly favors source-first lineage

The existing partner/competitor research highlights source-first/citation-first product patterns in financial AI and notes that Suno News content has especially strict requirements for entities, numbers, dates and attribution. The case contract explicitly requires a Factuality & Grounding Checker and dashboard source traceability. Therefore source lineage must be a first-class data model, not a presentation layer added after generation.

# DETERMINISTIC CHECKS

## 14. Numeric normalization and role-aware checking

### Required checks

1. Parse locale-aware decimal/grouping conventions (`1.234,56` vs `1,234.56`).
2. Normalize scales (`mil`, `milhão`, `bilhão`) and units.
3. Separate percentage (`%`) from percentage points (`p.p.`) and basis points (`bps`).
4. Preserve currency.
5. Preserve sign and direction.
6. Preserve range boundaries and comparator semantics (`acima de`, `até`, `entre`, `ao menos`).
7. Tie every numeric anchor to a semantic role (`receita`, `EBITDA`, `lucro`, `Selic`, `margem`) plus entity and period when available.
8. Handle explicit rounding as a configured transformation, not an implicit tolerance.
9. Treat derived numbers as valid only when operands, formula and source lineage are explicit/reproducible.

### Why raw numeric overlap is unsafe

Source: “receita líquida de R$ 10 bi; EBITDA de R$ 2 bi.”
Output: “o EBITDA foi R$ 10 bi.”

A naive number-presence checker passes because `10 bi` exists in the source. The role-aware checker fails because the `R$ 10 bi` anchor is bound to `RECEITA_LIQUIDA`, not `EBITDA`.

## 15. Dates and reporting periods

Normalize exact dates and semantic periods independently:

- `14/09/2026` → ISO date;
- `2T26`, `2º trimestre de 2026` → canonical quarter;
- `1S26` → canonical half-year;
- `12 meses encerrados em ...` → interval, not point date;
- YoY/QoQ comparisons must retain both reference periods.

A matching value from the wrong quarter is a contradiction for a claim that names the quarter.

## 16. Entity resolution

Use deterministic alias dictionaries and, when present in source, stable identifiers such as ticker or issuer metadata. Entity presence alone is not enough; the entity must be bound to the correct action/metric.

Examples of safe normalization:
- `Petrobras` ↔ `Petróleo Brasileiro S.A.` ↔ `PETR4` when source metadata confirms identity;
- abbreviations expanded only if unambiguous within the source.

An entity swap is `CRITICAL` when it changes who performed an action, issued guidance or owns a metric.

## 17. Negation, polarity and scope

Detect negation cues and their scope. Simple token presence is insufficient.

- source: “a companhia **não espera** reduzir investimentos”;
- output: “a companhia espera reduzir investimentos” → `CRITICAL` contradiction.

Avoid false positives for constructions such as “não apenas X, mas também Y”; the negation token does not negate proposition X.

## 18. Direction, comparator and transition checks

Normalize directional predicates:
- increase / decrease / stable;
- accelerate / decelerate;
- above / below;
- from A → B;
- expand / contract;
- beat / miss reference.

If source says “caiu de 10 para 8” and output says “subiu”, the numeric anchors may both be present yet direction is inverted. This is `CRITICAL`.

## 19. Conditions, modality and attribution

Claims must preserve epistemic status:
- `pode` ≠ `vai`;
- `espera` / `estima` ≠ realized fact;
- `se aprovado` ≠ approved;
- “a companhia afirma” ≠ independent verified fact;
- analyst projection ≠ company guidance.

Promotion of a conditional, estimate or possibility into an unconditional fact is `CRITICAL` when financially material.

## 20. Unsupported novelty

Every material generated claim must link to at least one supporting source span or be explicitly labeled as a permitted derived inference with traceable operands/rule. A plausible statement is still unsupported if the source does not contain it.

Example:
- source: “receita caiu 5%”;
- output: “a queda ocorreu por causa dos juros altos”;
- no source causal statement → `UNSUPPORTED`; severity `ERROR` or `CRITICAL` depending prominence/consequence.

# SEMANTIC GROUNDING LAYER

## 21. Claim extraction

Pipeline:

1. deterministic sentence segmentation;
2. deterministic detection of obvious anchors;
3. structured decomposition of compound sentences into atomic claims;
4. coverage audit: every sentence containing a material anchor must map to at least one claim;
5. preserve original sentence pointer so the UI can highlight exactly what was evaluated.

The decomposition model is a **parser**, not a truth authority.

## 22. Evidence retrieval

Use hybrid retrieval with **anchor-first bias**:

1. exact/canonical anchor candidates: entity + metric + number/date/period;
2. same-section and same-table-context expansion;
3. lexical/BM25 candidates;
4. embedding/semantic candidates;
5. evidence window expansion to adjacent spans only when needed for pronouns, conditions or table headers.

Candidate retrieval must return provenance. A retriever miss is not the same as a hallucination, so `UNVERIFIABLE`/`RETRIEVAL_MISS` should remain distinguishable from confirmed `UNSUPPORTED`.

## 23. Semantic verifier

For each `(claim, evidence_packet)` pair, produce at least:

```text
ENTAILS | CONTRADICTS | NEUTRAL/INSUFFICIENT | UNCERTAIN
```

Candidate families for implementation experiment:
- dedicated grounding fact-checker (MiniCheck-family);
- NLI baseline;
- alignment baseline (AlignScore-family or equivalent);
- structured LLM verifier only as an additional calibrated sensor.

Calibration must be performed on W001-T005 financial labels. No paper benchmark score is treated as project-level accuracy.

## 24. Optional QA escalation

For high-risk claims where deterministic checks pass but semantic support is uncertain, generate a targeted question from the claim and compare the source answer to the claim answer. This is an escalation sensor inspired by QAFactEval, not a mandatory second judge on every claim.

Examples:
- “Qual foi a margem EBITDA no 2T26?”
- “A companhia condicionou o pagamento de dividendos a qual evento?”
- “A projeção é guidance da companhia ou estimativa externa?”

## 25. Decision precedence

Recommended precedence:

```text
1. SOURCE EXTRACTION TRUST GATE
2. DETERMINISTIC CRITICAL CONTRADICTIONS
3. DETERMINISTIC SUPPORT/MISMATCH SIGNALS
4. SEMANTIC ENTAILMENT/CONTRADICTION
5. OPTIONAL QA ESCALATION
6. STRUCTURED LLM EXPLANATION / TRIAGE
```

Rules:
- a deterministic `CRITICAL` mismatch cannot be overridden by semantic entailment;
- low extraction confidence on a source span used for a critical claim blocks automatic `PASS`;
- semantic contradiction with strong calibrated evidence causes failure even if anchors happen to match;
- multi-model agreement is never treated as ground truth;
- unresolved disagreement is surfaced as `AMBIGUOUS`/`UNVERIFIABLE` for repair or human review.

# SEVERITY AND FAIL POLICY

## 26. Severity classes

| Severity | Meaning | Examples | Policy |
|---|---|---|---|
| `INFO` | lineage/diagnostic detail with no factual risk | benign alias normalization | pass; log |
| `WARN` | uncertainty, weak retrieval or low-risk ambiguity without known contradiction | evidence packet incomplete for non-material wording | pass only if no material claim is unresolved; surface warning |
| `ERROR` | unsupported/ambiguous material claim or meaningful semantic mismatch | unsupported causal explanation; evidence not found for material assertion | targeted repair/re-evaluate; no final factual PASS while unresolved |
| `CRITICAL` | deterministic or semantically clear corruption of financial truth | wrong number/unit/entity/metric/period, direction inversion, negation inversion, conditional→fact, unreliable extraction on critical anchor | hard fail; block output until corrected or explicitly human-reviewed |

## 27. Non-compensable hard gates

Recommended factuality `PASS` conditions:

1. **zero unresolved `CRITICAL` findings**;
2. **zero unresolved `ERROR` findings on material claims**;
3. every material claim has explicit evidence lineage or a permitted deterministic derivation trail;
4. every generated critical anchor is validated against evidence in the correct semantic role;
5. no critical claim depends exclusively on a `LOW` extraction-confidence source span;
6. source-lineage coverage for material claims is complete for auto-pass.

Do **not** average these conditions into a single scalar that allows high readability or style quality to compensate for factual corruption. A diagnostic score may exist for comparison, but gates remain independent.

Quantitative confidence thresholds for NLI/alignment, OCR/extraction and retry behavior must be calibrated in W001-T005/T009 rather than invented here.

## 28. Suggested diagnostics

- `material_claim_support_rate`
- `unsupported_material_claim_rate`
- `contradicted_material_claim_rate`
- `generated_anchor_validity_rate`
- `required_anchor_recall` for a gold-labeled must-preserve subset
- `critical_anchor_error_count`
- `source_lineage_coverage`
- `low_confidence_evidence_dependency_rate`
- error counts by taxonomy: number / unit / entity / metric / period / polarity / condition / attribution / causality
- slices by document family × audience × format.

These metrics are diagnostic and experimental; the hard-fail conditions above remain non-compensable.

# PDF EXTRACTION CONFIDENCE STRATEGY

## 29. Principle

`RISK-0010` means a semantic verifier can falsely “prove” a hallucination if the extracted text itself is wrong. Therefore grounding confidence must begin **before generation**.

## 30. Provenance-preserving extraction

For every extracted span, preserve when available:
- page number;
- bounding box / coordinates;
- block/table identity;
- extraction route (`NATIVE_TEXT`, `OCR`, `TABLE_PARSER`);
- parser/version;
- source file hash;
- table row/column headers, units and periods;
- confidence signals.

The dashboard should open the original page and highlight the evidence region, not merely show the normalized extracted string.

## 31. Page-level extraction routing

Recommended routing:

1. detect whether a page has a usable native text layer;
2. use native extraction first for born-digital text;
3. trigger OCR selectively for scanned/garbled regions instead of OCRing every PDF by default;
4. use table-aware extraction for detected tables;
5. reconcile critical anchors when two extraction routes disagree.

This is a design proposal, not a claim that one parser is universally best. W001-T006/build experiments should compare parser options on the three target document families.

## 32. Extraction confidence signals

Represent confidence as a class plus reasons until empirically calibrated; avoid an arbitrary weighted average now.

Potential signals:
- native text layer present/absent;
- OCR confidence if OCR is used;
- reading-order anomalies;
- character corruption rate;
- parser disagreement on critical numbers/entities;
- table header/cell binding completeness;
- duplicate/missing lines;
- footnote loss suspicion;
- anchor checksum inconsistencies;
- unusually low anchor coverage versus source preview.

Policy:
- `HIGH`: stable extraction with provenance and no critical disagreement;
- `MEDIUM`: usable but one or more uncertainty signals; semantic checks allowed, warnings retained;
- `LOW`: critical uncertainty, unresolved parser disagreement, broken table lineage or OCR ambiguity; any material claim depending solely on it cannot auto-pass.

## 33. Table-specific guardrail

For a claim sourced from a table, evidence is invalid if the system cannot recover enough context to identify:
- row concept;
- column/period;
- unit/currency;
- cell value.

A naked cell number is not acceptable grounding evidence.

## 35. False-positive traps the evaluator must avoid

1. **Legitimate rounding:** source `10,04%` → output `10,0%` when rounding policy explicitly permits one decimal. Exact string matching would falsely fail.
2. **Aliases:** `Petróleo Brasileiro S.A.` vs `Petrobras`/ticker when source metadata confirms identity.
3. **Paraphrase:** semantic support can exist without lexical overlap; deterministic lexical check alone would falsely fail.
4. **Negation scope:** “não apenas X, mas também Y” must not be interpreted as negating X.
5. **Derived arithmetic:** source gives operands and output states a transparent derived percentage; valid only with reproducible formula/provenance.
6. **Unit-equivalent normalization:** `R$ 1.000 milhões` and `R$ 1 bilhão` can be equivalent if scale normalization is correct.
7. **Date paraphrase:** “no segundo trimestre de 2026” and `2T26` are equivalent.

## 36. False-negative traps the evaluator must catch

1. Same number appears in source but belongs to a different metric.
2. Same entity appears in evidence but the action is performed by another entity.
3. Correct value is attached to the wrong period.
4. Source contains both positive and negative scenarios; retriever selects the wrong conditional branch.
5. NLI model over-trusts lexical overlap and misses a comparator/direction inversion.
6. Semantic verifier validates a generator against an OCR-corrupted extraction; extraction confidence must veto auto-pass.
7. Retrieval misses the relevant evidence; system must distinguish retrieval failure from proven unsupportedness.
8. A compound sentence contains one true and one false proposition; atomic decomposition prevents a whole-sentence score from hiding the false subclaim.

Per output, show:
- material claims count;
- supported/unsupported/contradicted/unverifiable counts;
- critical anchor errors;
- lineage coverage;
- extraction warnings;
- retry/repair history.

The UI should emphasize hard failures rather than a reassuring aggregate “95/100”. If one claim has a `CRITICAL` wrong number, the output is not factually safe even if all other metrics are excellent.


This supports `REQ-013/017` downstream without forcing full regeneration and reduces the chance that repair introduces fresh factual drift.

# DECISIONS_PROPOSED

1. **Adopt claim-level evaluation** as the factuality unit, with atomic decomposition and full material-claim coverage.
2. **Adopt deterministic veto precedence** for high-risk anchors; semantic scores cannot override critical deterministic contradictions.
3. **Adopt semantic NLI/alignment as a second layer**, with optional QA escalation for ambiguous/high-risk claims.
4. **Make source provenance mandatory** at page/span/table-cell level; no fabricated or detached citations.
5. **Treat extraction confidence as part of factuality**, not a separate parser concern; low-confidence critical evidence blocks auto-pass.
6. **Use non-compensable factuality hard gates**, not a single average score.
7. **Do not lock semantic thresholds yet**; calibrate against W001-T005 financial golden/held-out data.
8. **Do not use multi-agent or LLM consensus as truth.** Models can provide independent sensors/explanations only.
