## Implementation

### F1 — fixed-bank fail-closed operator

src/suno_content/annotation/operator.py:

- reads only the fixed W004-T002 blind bank;
- checks schema/plan/rubric versions and blinding flags;
- requires exactly 36 items;
- rejects nested target/evaluator/generator/peer fields;
- rejects explicitly held-out items;
- supports only PRIMARY_A and PRIMARY_B;
- never accepts an arbitrary annotation corpus path.

The real W004 blind packet uses opaque blind_item_id values; the operator accepts that opaque-ID shape without revealing generation targets.

### F2 — independent role-locked sessions

Each primary session stores a random non-secret session ID, fixed role, pseudonymous annotator ID, contract versions, decoded blind-bank SHA-256, frozen 36-item order, and only that primary's records.

Records cannot change role or annotator identity, duplicate items, or reference items outside the frozen bank. PRIMARY_A cannot be imported into PRIMARY_B.

The operator cannot prove that two files came from two physical people, so genuine human independence remains an operational requirement. The instructions require separate humans, workspaces/sessions, and frozen exports before cross-annotator review.

### F3 — explicit entry, progress, strict import/export

The local entry point exposes validate, init, status, show, annotate, submit, import, and export. Interactive annotation requires explicit D1-D5, global audience label, mixed-level flag, non-compensatory checks, confidence, and notes; no label is inferred or defaulted.

Export requires all 36 items exactly once and writes schema-compatible JSONL plus a provenance sidecar. Import requires an empty matching primary session and a complete role/annotator-compatible stream; it never merges streams.
