## 2. Question and proof case

EXP-B asks whether LangGraph `StateGraph` reduces orchestration/recovery complexity enough to justify itself over a plain-async Python baseline while satisfying the explicit graph-with-state requirement.

The two implementations use the same deterministic mock contract and the same 3×3 topology:

- 9 audience×format jobs;
- exactly one deliberate first-pass quality failure: `beginner:carousel`;
- repair only for that branch;
- keyed join that must retain all 9 outputs;
- checkpoint/resume path;
- inspectable execution/state history;
- explicit reducer/state-loss risk exposure.

No model/provider performance is being benchmarked. The mock uses zero-I/O deterministic work so framework/control-flow behavior is isolated from LLM latency.

## 7. Reducer/state-loss finding

The critical framework-specific hazard is parallel writes to a shared state key.

For any LangGraph implementation in this project, `outputs`, `evaluations`, repair metadata or event collections written concurrently must not use default single-value semantics. They need reducers with explicit invariants. For maps, the safe pattern in this experiment is:

- merge by immutable `job_id`;
- preserve all disjoint keys;
- treat duplicate `job_id` writes as a hard error rather than last-write-wins;
- keep the reducer deterministic and associative for parallel execution.

`langgraph_hazards.py` intentionally omits the reducer so a networked environment can verify that concurrent writes are rejected rather than silently losing state.

Plain async avoids a framework reducer contract because each branch returns independently and the join constructs the keyed map centrally, but duplicate identity validation is still required. Therefore the domain invariant — keyed branch identity and no silent overwrite — is framework-neutral and should be locked regardless of final orchestrator.

## 8. Kill criterion applied

W001-T010 defined the EXP-B kill criterion: fall back to the simple engine if the required behaviors need substantial custom machinery or introduce silent state-loss/reducer hazards absent from the baseline.

### Decision from evidence available in this attempt

**Recommend plain async Python as the provisional orchestrator. Do not lock LangGraph yet.**

Rationale:

1. plain async executed every required semantic in the proof case with a small surface;
2. LangGraph's most valuable claimed advantages here — first-class checkpoint/recovery/history — were implemented but could not be runtime-proven in this environment;
3. parallel LangGraph state adds a reducer correctness obligation that is easy to misuse unless made explicit and adversarially tested;
4. framework identity is not a domain requirement and must not be selected from preference;
5. the same framework-neutral contracts preserve a cheap future substitution.

This is **not** a permanent rejection of LangGraph. The challenger remains viable. A networked/CI run of the included tests can reopen the decision if it demonstrates clean 9-way fan-out, lossless reducer merge, local repair, checkpoint/resume/history and no substantial workaround burden. Until then, evidence does not justify granting LangGraph a provisional lock.
