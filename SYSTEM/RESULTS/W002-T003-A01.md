## Executive result

Implemented an independent deterministic policy slice that converts the W001 policy findings into executable `PASS | REVIEW_REQUIRED | FAIL` semantics without allowing soft signals, disclaimers, or formatting pressure to compensate for substantive policy failures.

The implementation deliberately separates two responsibilities:

1. high-precision lexical detection for obvious recommendation/personalization/disclaimer patterns; and
2. explicit semantic/provenance signals for facts that cannot be safely proven by keyword matching alone (attribution, modality, caveat loss, source mixing, extraction confidence, external context, normative distortion).

This avoids pretending that a regex can prove source equivalence while still giving the pipeline deterministic gates today.

## Implemented policy taxonomy

### Non-compensatory hard fails

- `HF-01` unsupported/new recommendation, target, allocation or investment action;
- `HF-02` personalized investment action;
- `HF-03` material grounding mismatch signal;
- `HF-04` modality escalation;
- `HF-05` attribution loss / recommendation laundering;
- `HF-06` unverified/non-public source in the public-source scope;
- `HF-07` fabricated internal policy/disclaimer/regulatory endorsement;
- `HF-08` risky output with unresolved source type or business context;
- `HF-09` normative distortion;
- `HF-10` material caveat elision;
- `HF-11` untraceable source mixing — implementation extension for the explicit W001 prohibition on mixing claims from distinct sources without claim-level provenance.

`HF-11` is proposed as a dedicated integration code because W001 specified the prohibition but did not assign it a unique hard-fail identifier. The fan-in may alias the code to a grounding/provenance code, but the hard-fail semantics must remain non-compensatory.

### First-class human review

- `HR-01` source contains recommendation/rating/target/portfolio content;
- `HR-02` sensitive corporate event/guidance;
- `HR-03` practical legal/regulatory-effect summary;
- `HR-04` low-confidence source extraction/provenance;
- `HR-05` recommendation detector/provenance disagreement;
- `HR-06` external context added beyond the primary source.

Decision precedence is explicit: any hard fail => `FAIL`; otherwise any review finding => `REVIEW_REQUIRED`; otherwise `PASS`. Review findings remain visible even when a simultaneous hard fail controls the terminal decision.

## Disclaimer and internal-policy boundary

A disclaimer is detected only as audit metadata. It has **zero decision-changing power**. The adversarial case “Isto não é recomendação. Se você é investidor conservador, compre X...” remains `FAIL/HF-02`.

No Suno business-unit policy, legal wording, approval workflow, or official disclaimer was invented. `business_context` defaults to `UNKNOWN` and `configured_disclaimer_id` defaults to `None`. Unknown business context is permitted for non-risky educational transformation, but a recommendation-like/asset-specific output with unresolved source/business context triggers `HF-08`.

## Integration notes

1. This slice is intentionally independent of W002-T001. At the W002-T008 fan-in, adapt/replace the local `SourceType`/context boundary with accepted domain schemas from T001 rather than duplicating canonical domain types. Preserve behavior and tests.
2. `PolicySignals` is the contract boundary for semantic/provenance sensors. Factual backbone/claim-lineage work can set these booleans/enums without coupling the policy decision function to a specific semantic model.
3. `RecommendationProvenance.UNKNOWN` routes to `HR-05`, not PASS. A source recommendation with `attribution_preserved=True` routes to `HR-01`; `False` becomes recommendation laundering (`HF-01 + HF-05`).
4. `configured_disclaimer_id` is configuration-only and intentionally unused as a suppressor. Future approved disclaimer rendering must never change hard-fail semantics.
5. `HF-11` needs explicit acceptance/alias decision at fan-in; its semantics are required even if the code name changes.
