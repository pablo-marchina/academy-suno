## Outcome

The task's research/benchmark deliverable is complete. The evidence does **not** justify a production parser winner. The decision record is intentionally `PENDING_EVIDENCE / NO_PRODUCTION_PARSER_WINNER` while materially narrowing the architecture and candidate set.

The strongest result is that Academy Suno's existing fail-closed source-trust posture is correct and must remain invariant: text/number presence cannot substitute for page/table/cell provenance. The W004 `pypdf`/`pdftotext` path is suitable as text-layer preflight/fallback, but table-bearing documents cannot become `SOURCE_READY` from flat text alone.

## Findings / evidence

### F1 — Baseline can preserve every critical number while preserving zero provable table roles

Repository baseline review found:

- `src/suno_content/ingest/adapters.py` explicitly marks table-looking flat text as role-ambiguous for pypdf/pdftotext;
- `src/suno_content/ingest/service.py` permits `SOURCE_READY` only with high confidence, no table-role ambiguity and HIGH trust;
- `src/suno_content/grounding/provenance.py` requires resolvable source lineage and either span provenance or table `(row_index, column_index)` provenance;
- `tests/fixtures/parser/silent_corruption_cases.json` already encodes the two exact corruption classes this task must defend: metric-role swap and table-role drop.

Current pypdf documentation independently confirms the underlying reason: PDF has no semantic layer, tables are usually positioned text, and pypdf is not OCR.

### F4 — Materially different parser/document-intelligence classes were covered

The DR compares:

1. current pypdf/pdftotext text-layer baseline;
2. PyMuPDF local geometric/table extraction;
3. pdfplumber local geometric/table extraction;
4. Docling local ML layout/table/OCR document intelligence;
5. Amazon Textract managed TABLES/LAYOUT;
6. Azure Document Intelligence Layout;
7. Google Document AI Gemini Layout Parser.

Primary documentation shows that the three managed services and Docling expose materially richer layout/table primitives than flat-text extraction. AWS exposes row/column indices, spans, geometry and table cell entity types; Azure exposes spans/polygons, paragraph roles and structured tables/merged-cell markup; Google detects structural PDF elements but documents a 15-page online / 500-page batch limit and possible splitting of multi-page tables; Docling's unified representation carries tables, hierarchy, bounding boxes and provenance.

### F5 — Cost/licensing/operations prevent premature winner selection

- PyMuPDF is AGPL/commercial dual licensed, so deployment licensing is material.
- pdfplumber and Docling codebases are MIT (individual Docling model licenses still require review).
- AWS publishes a Tables example at `$0.015/page` for the first 1M pages/month in US West (Oregon), `$0.010/page` thereafter; region/features alter cost.
- Google exposes Layout Parser / OCR consumption pricing, but purchase-time units/model must be revalidated.
- Azure exposes a 500 pages/month free tier, while the research crawler did not surface stable numeric S0 regional prices; no price was invented.
- Managed candidates were not executed because worker credentials/billing context were unavailable; Docling was not installed in the worker runtime. These remain explicit evidence gaps.

## Decision proposal

Keep parser/document-intelligence selection **unlocked**.

Advance a parser-agnostic, evidence-completeness cascade for implementation/bakeoff:

`text-layer preflight -> scan/table/ambiguity classification -> structured local and/or managed parser -> canonical ParsedDocument normalization -> invariant source-trust gate`.

A fallback parser may recover content, but **parser success/no-exception may never increase trust by itself**. Table-derived evidence is eligible only when normalized cell roles and provenance are resolvable. OCR text without structure remains `REVIEW_REQUIRED` for table claims.

Candidates advancing to the same-corpus bakeoff: PyMuPDF, pdfplumber, Docling, Textract, Azure Document Intelligence and Google Document AI. This is a shortlist, not a ranking.
