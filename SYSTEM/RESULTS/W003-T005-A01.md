### 3.2 Single reproducible foundation runner

It executes, in one checkout and one environment:

- `compileall` over `src`, `tests`, and `experiments`;

  - `tests/unit/domain`;
  - `tests/factual`;
  - `tests/policy`;
  - `tests/formats`;

  - `tests/experiments/orchestration`;

- explicit parser contract assertions:
  - structured reference must PASS all observed fixtures;
  - flat-text table-role loss must remain `REVIEW_REQUIRED`;
  - wrong-role silent corruption must remain a hard `FAIL`;
- the W002 orchestration benchmark;
- persisted step logs plus a machine-readable `manifest.json` in the configured artifact directory.

Any non-zero subprocess result or parser-contract drift fails the runner. No compatibility error is converted into a warning-only green path.

### 3.3 Separate application/foundation CI

Added `.github/workflows/foundation-tests.yml` with check name `clean-checkout-foundation`.

The workflow is intentionally separate from `System Integrity` and performs:

- `actions/checkout@v4` clean repository checkout;
- Python 3.13 setup;
- pinned W002 runtime-evidence dependencies:
  - `pydantic==2.13.4`;
  - `pytest==9.0.2`;
- execution of `python experiments/foundation_regression/run_foundation_regression.py`;
- upload of `/tmp/foundation-regression` evidence with `actions/upload-artifact@v4`, including on failures.

It triggers on PRs and main pushes that touch `src/**`, `tests/**`, `experiments/**`, or the foundation workflow itself. `System Integrity` remains responsible for canonical-system validation under its existing workflow.
