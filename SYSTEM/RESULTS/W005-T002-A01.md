## Material findings

### Native EventSource auth must be designed, not assumed

Native browser EventSource provides URL and credentials mode rather than arbitrary header configuration. Same-origin secure HttpOnly session-cookie SSE is straightforward; a bearer-header-only design needs a deliberate fetch-stream/polyfill/BFF choice. This is handed to W005-T004.

### WebSocket is not “better” merely because framing is smaller

RFC framing is efficient, but classic browser WebSocket has no built-in backpressure and transport alone provides no durable replay. Its bidirectionality becomes valuable for real concurrent editor collaboration, not for a server-to-browser run feed whose commands already use HTTP.

### Framework selection is intentionally not frozen

React+Vite is a leading candidate if Python remains the authoritative API because Vite can emit static production assets. Next.js remains credible where SSR/BFF/server UI composition produces measurable value.

A framework lock now would violate the DRG because:
- no production JS workspace/package manager is yet selected;
- no same-slice bundle/build/CI/deploy benchmark exists;
- W005-T013 was explicitly added to decide these toolchain boundaries.

### Editor selection is intentionally not frozen

Tiptap and Lexical each have viable structured-content/collaboration paths but different coupling and operational assumptions. The deciding spike must test Academy-specific citation/provenance behavior rather than editor demos.
