## 5. Anti-circularity contract

The benchmark freezes this separation:

```text
generation_target_level != human_gold_level != evaluator_predicted_level
```

A generation request such as `ADVANCED` is merely the treatment/target given to the generator; it is not evidence that humans perceive the output as Advanced.

The annotator schema deliberately has no properties for:

- `generation_target_level`;
- evaluator prediction/scores;
- generator identity;
- prompt version;
- expected label;
- peer annotations before independent submission.

`gold_labels` is empty in the v001 manifest. A label may be promoted only with independent human annotation provenance and `gold_label_source=BLIND_HUMAN_ADJUDICATION`; the validator rejects automatic target-as-gold promotion semantics.

### 6.1 Audience labels

### 6.2 Audience dimensions

The rubric versions five ordinal observations before the global judgment:

1. `D1_JARGON_CONTEXTUALIZATION`;
2. `D2_BACKGROUND_ASSUMED`;
3. `D3_CONCEPTUAL_DEPTH`;
4. `D4_CONTENT_FOCUS`;
5. `D5_TECHNICITY_PRESERVATION`.

The global audience label is not a blind arithmetic mean. Materially conflicting dimensions require `mixed_level_flag`; outputs without a defensible dominant class may be `UNSCORABLE`.

### 6.3 Non-compensatory checks

Audience fit/readability cannot buy its way out of truth loss. Annotation records separately capture:

- `FACTUAL_CRITICAL_PRESERVATION`;
- `MATERIAL_CONCEPT_PRESERVATION`;
- `FORMAT_NATIVE_CONTRACT` when applicable.

This preserves `CRIT-001` and prevents the main anti-gaming failure mode: making a text appear easier by deleting material concepts or qualifiers.

## 7. Agreement / review workflow

Artifact: `docs/evals/gold_benchmark_v001.md`.

Reproducible lifecycle:

1. freeze source/output identity and hashes;
2. prepare blind annotation packet with target/evaluator/generator/prompt/peer labels removed;
3. `PRIMARY_A` annotates independently;
4. `PRIMARY_B` annotates independently;
5. measure pre-adjudication raw agreement, disagreement rate, `UNSCORABLE` rate and Cohen's kappa when applicable;
6. route disagreements/UNSCORABLE/non-compensatory conflicts to a distinct `ADJUDICATOR` with rationale;
7. promote human gold only with annotation IDs and adjudication provenance;
8. calibrate evaluator only on development gold;
9. freeze evaluator/rubric/threshold versions before declared held-out evaluation.

No actual Suno employee/annotator role is assumed. These are benchmark functions, not claims about partner staffing.

## 8. Leakage / instability kill criteria

The benchmark cannot support calibration/release claims if any of the following occurs:

- outputs from one source cross splits;
- held-out evidence informs tuning, feature selection, prompt design or iterative error analysis;
- requested target is reused as human gold;
- annotators see evaluator outputs/expected labels/peer labels before independent submission;
- a single annotation is silently promoted to gold;
- source/output/annotation provenance is unreconstructible;
- schema/rubric changes without a version bump;
- agreement remains unstable/non-reproducible after rubric review;
- source/slice sample is too small or imbalanced for the claimed threshold;
- factual/material-concept failures are compensated by audience/readability metrics.

The required disposition under insufficient evidence is diagnostic-only, not threshold fabrication.
