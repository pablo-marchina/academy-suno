# 3. Executive decision

A arquitetura candidata recomendada é uma **pipeline source-first pequena, stateful, auditável e não agentic por default**:

```text
SOURCE
  → INGEST / PARSE
  → SOURCE TRUST + FACTUAL BACKBONE
  → POLICY CONTEXT
  → 3×3 FAN-OUT (audience × format)
  → STRUCTURED GENERATION
  → HYBRID EVALUATION PER VARIANT
  → TARGETED REPAIR ONLY WHERE NEEDED
  → RE-EVALUATION
  → 3×3 EVIDENCE COCKPIT + RUN MANIFEST
```

Leading stack candidate:

- **Python tipado** como core;
- **LangGraph StateGraph** para o workflow explícito com state, fan-out, conditional repair e checkpoint/resume;
- **Pydantic** nas fronteiras de domínio/I/O e contratos persistidos;
- **TypedDict/dataclass** para state runtime quando validação Pydantic em cada update não agregar valor;
- **parser adapter** desacoplado de fornecedor, com source spans/page/table provenance e fallback explícito;
- **custom deterministic eval layer + pytest** como base de correção;
- **semantic grounding/audience backends plugáveis**, nunca autoridades únicas;
- **SQLite + JSON/JSONL** para RunStore, manifests e telemetry da demo; checkpointer persistente fora da UI;
- **Streamlit** como thin evidence-cockpit/demo adapter;
- provider/model, parser final, semantic backend e thresholds permanecem **PENDING_EXPERIMENT**.

A arquitetura alternativa deliberadamente mais simples é **plain async Python + Pydantic/dataclasses + SQLite/JSONL**, preservando exatamente os mesmos contratos e targeted repair. Ela é o baseline e fallback obrigatório contra overengineering.

A recomendação não é “LangGraph porque é moderno”. LangGraph lidera porque o briefing exige grafo com estado, 3×3, refinamento condicional, rastreabilidade e prova de execução; o framework pode materializar essas propriedades com menor superfície custom do que um engine próprio. Se o smoke test revelar complexidade desproporcional, o fallback simples vence.

O diferencial do case deve ser apresentado como **content transformation + trust layer**, não como framework, RAG sofisticado, multiagentes ou “voz Suno” simulada.

# 4. Invariantes arquiteturais

## 4.1 Uma verdade factual antes de nove narrativas

O sistema parseia e valida a fonte uma vez, produz um `FactualBackbone` comum e só então cria 9 `VariantJob`s. Audience e format são dimensões independentes; `source_type/content_type/business_context` são overlays de policy.

## 4.2 Source corruption não pode virar generation problem

Parser/extraction é hard boundary. Se um anchor crítico depende de extração ambígua/LOW ou tabela incompleta, o pipeline deve ir para fallback/review; não deve pedir ao LLM que “reconstrua” fatos ausentes.

## 4.3 Factual/policy hard gates são não compensáveis

Nenhum ganho em Flesch, estilo, density, hook, engagement ou classificação de audiência compensa:

- contradição factual crítica;
- material claim sem suporte resolvido;
- perda de conceito material requerido;
- perda de technical label explicitamente requerido;
- recommendation/personalized advice criada pelo sistema;
- modality/attribution distortion;
- caveat material apagado para caber no formato;
- norma/regulação materialmente distorcida.

## 4.4 Repair é local e diagnóstico

Falha em uma célula não regenera a matriz. Repair recebe:

- output anterior;
- failed constraints;
- exact diagnostics;
- immutable factual backbone;
- relevant policy/format/audience contracts;
- source refs.

Depois, somente a variante reparada é reavaliada.

## 4.5 UI não é state store

Streamlit controla interação e visualização; workflow state, manifests, outputs, evals e telemetry são persistidos fora de session state.

## 4.6 Auditability precede sophistication

OpenTelemetry/LangSmith, GraphRAG, multi-agent planning, durable engines externos e frontend separado são adapters/opções futuras, não correctness dependencies do MVP.

## 5.1 Run state machine

```text
CREATED
→ SOURCE_INGESTED
→ PARSED
→ SOURCE_VALIDATING
    ├─ SOURCE_BLOCKED
    ├─ REVIEW_REQUIRED
    └─ SOURCE_READY
→ GENERATING
→ EVALUATING
    ├─ ACCEPTED
    ├─ REPAIRING → EVALUATING
    ├─ REVIEW_REQUIRED
    └─ FAILED
→ AGGREGATING
→ COMPLETE | COMPLETE_WITH_REVIEW_ITEMS | FAILED
```

Transport/system retry is separate from this quality lifecycle. A provider timeout may retry the node; an evaluator failure routes to targeted repair; a source-trust failure routes to source fallback/review.

# 6. Deliberately simpler alternative

## 6.1 Architecture

```text
parse_source()
→ validate_source()
→ build_backbone()
→ build_jobs(3×3)
→ asyncio.gather(generate(job) for job in jobs)
→ asyncio.gather(evaluate(job) for job in outputs)
→ asyncio.gather(repair(job) only for repairable failures)
→ re_evaluate(repaired)
→ persist RunResult
```

Components:

- Python async/task groups;
- Pydantic/dataclasses;
- explicit finite-state enum;
- SQLite RunStore;
- JSONL telemetry;
- same evaluator and policy packages;
- same Streamlit UI.

## 6.2 When the simple alternative wins

Switch to it if LangGraph fails the local proof of:

1. 9-way fan-out keyed by `job_id`;
2. deterministic join without branch overwrite;
3. one-branch failure + branch-local repair;
4. checkpoint/resume of an interrupted run;
5. inspectable transition history;
6. implementation without substantial framework workarounds.

The core contracts must make this substitution cheap. Framework identity is not part of domain state.

## 6.3 Limitation

A hidden script/FSM alone is weaker evidence for explicit `REQ-002 — workflow baseado em grafo com estado`. If fallback becomes final, the team must still demonstrate an explicit graph/state representation rather than pretending sequential control flow satisfies the requirement.

# 7. Stack recommendation with trade-offs

| Layer | Candidate | Why now | Main risk | Fallback / lock condition |
|---|---|---|---|---|
| Language/core | Python typed | natural fit for NLP/LLM/eval ecosystem and case speed | weak discipline can create dict soup | schemas/tests required |
| Workflow | LangGraph StateGraph | first-class state, conditional edges, fan-out, reducers, checkpointing | framework semantics/overhead | plain async engine if smoke test fails |
| Domain schemas | Pydantic | strict persisted/I/O contracts and structured model outputs | over-validation in hot state updates | TypedDict/dataclass runtime state |
| Parsing | `ParserAdapter` abstraction | preserves replaceability while A-0008 is open | silent PDF/table corruption | test target families; add fallback(s) based on evidence |
| Deterministic eval | custom modules + pytest | case requires reproducibility and anti-gaming | implementation detail/error surface | fixtures + property/adversarial tests |
| Semantic grounding | pluggable NLI/alignment/structured judge | needed for support beyond exact anchors | circularity, cost, false confidence | remove backend if ablation adds no material value |
| Audience classifier | calibrated model/rule layer over frozen features | case requires measurable distinction between levels | small gold / overfit | keep diagnostic until development calibration proves utility |
| Persistence | SQLite + versioned JSON/JSONL artifacts | enough for demo, audit and reproducibility | concurrency/locking if scale grows | Postgres only if measured need appears |
| Graph persistence | local persistent checkpointer | satisfies resume/demo without distributed infra | library-specific coupling | RunStore remains framework-neutral source of audit |
| UI | Streamlit | fastest path to dense 3×3 evidence cockpit | rerun/session semantics, demo layout | switch adapter only if demo acceptance fails |
| Service API | defer FastAPI | no proven external client requirement | scope/ops expansion | add later without changing core |
| Observability | custom `TelemetryEvent` + run aggregates | correctness-owned, portable, inspectable | less fancy tracing | optional OpenTelemetry/LangSmith adapters later |
| Durable engine | defer Temporal/DBOS/Prefect/etc. | no long-running distributed requirement evidenced | overengineering | introduce only from real adoption requirement |
| Multi-agent/GraphRAG | reject by default | not needed for stated problem | cost/circularity/demo noise | reconsider only after measured unmet requirement |

### Stack lock posture

**Propose locking now:** Python typed contracts, source-first backbone, non-compensatory evaluator semantics, branch-local repair, UI-agnostic core, versioned persistence/telemetry.

**Propose provisional selection:** LangGraph + Pydantic + Streamlit + SQLite/JSONL.

**Do not lock yet:** parser implementation, LLM/model/provider, semantic grounding backend, audience classifier algorithm, final repair cap, calibrated thresholds/floors, price table/provider-cost configuration.

# 9. Hybrid decision order + policy reconciliation

Recommended final decision order:

```text
1. source provenance exists and source is in allowed public scope
2. source trust / extraction critical gate
3. deterministic factual anchors
4. atomic material claim grounding
5. required concepts / required technical labels
6. content-policy hard fails + review triggers
7. format-native contract
8. Audience Complexity Vector + calibrated audience decision
9. structured semantic/LLM sensor where applicable
10. non-compensatory HybridDecision
```

This order prevents a polished output from hiding upstream corruption.

### Mandatory policy behavior

- system is an **adapter/explainer**, not autonomous investment recommender;
- unsupported recommendation/personalized advice is hard fail;
- disclaimer never bypasses substantive controls;
- source recommendation may survive only with explicit attribution/provenance and configured review policy;
- business/unit-specific Suno policy remains `UNKNOWN` until externally confirmed;
- human overrides are auditable and do not silently rewrite evaluator truth.

### Human-review route

The product must preserve a first-class `REVIEW_REQUIRED` state for sensitive source types, ambiguous extraction, recommendation-bearing research, forward-looking/guidance, material legal interpretation, source-mixing or manual hard-rule exception. This is not a “soft PASS”.

# 10. Audience/content calibration reconciliation

From T001 + T009:

- **Beginner:** accessibility, explanation/analogy and practical meaning are required, but cannot delete material mechanisms/qualifiers;
- **Intermediate:** standard market vocabulary, drivers and “why it matters”; facts and implications remain separated;
- **Advanced:** preserve method, assumptions, full technical labels/jargon when required, limitations and causal structure; high Flesch is not an objective by itself.

From T001:

- `audience_level`, `format` and `content_type/source_type` must remain separate dimensions;
- Suno public patterns are soft calibration signals, not hard brand-voice rules;
- educational, news, technical/research and short-form contexts require different structural expectations.

From T009:

- final audience thresholds/classifier acceptance policy are calibrated on development gold and frozen before held-out;
- `generation_target_level`, `human_gold` and `evaluator_prediction` remain distinct;
- held-out cannot be used for tuning;
- ACV is multidimensional and must not collapse into one unvalidated linear score.

The UI contract should be treated as product evidence, not decoration.

- re-run evaluator/source trace locally when possible;
- never claim cached generation/repair happened live;
- preserve error/provider state honestly.

This is more credible than risking a full demo failure or fabricating a live PASS.
