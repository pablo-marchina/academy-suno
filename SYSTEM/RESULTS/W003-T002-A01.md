## 3. Implementation

Implemented B08 under `src/suno_content/grounding/**`.

### 3.1 Atomic claims and resolvable evidence

Added immutable/versioned contracts for:

- `AtomicClaim` with materiality, anchor IDs and mandatory canonical `ProvenanceRef` evidence pointers;
- `EvidenceItem` / `EvidencePacket` with retrieval version and explicit extraction status;
- `ProvenanceResolver` over canonical `ParsedDocument`, source spans and table cells;
- validation that expected claim evidence is resolvable even when retrieval returns zero candidates.

This makes a true retrieval miss distinguishable from invented/unresolvable provenance.

### 3.2 Four claim support states without uncertainty collapse

Claim-level support is represented as exactly:

- `SUPPORTED`;
- `CONTRADICTED`;
- `UNSUPPORTED`;
- `UNVERIFIABLE`.

`UNVERIFIABLE` carries a typed reason. In particular:

- `RETRIEVAL_MISS` is emitted when expected provenance is valid but retrieval returns no evidence;
- `EXTRACTION_AMBIGUITY` is emitted when source/evidence extraction cannot be trusted;
- `SEMANTIC_NOT_RUN`, `SEMANTIC_UNCERTAINTY` and `HARD_GATE_BLOCKED` remain separately auditable.

Retrieval/extraction failures therefore never become confirmed `UNSUPPORTED` claims.

### 3.3 Unified HybridDecision with absolute precedence

Added versioned `GateSignal`, `ClaimFinding` and `HybridDecision` contracts plus `hybrid_decision()`.

Decision order is structural rather than score-based:

```text
SOURCE hard gate
→ DETERMINISTIC FACTUAL hard gate
→ POLICY hard gate
→ claim-level grounding
→ semantic sensor only when upstream evidence/gates permit
```

`HybridDecision` has a Pydantic invariant that rejects a PASS whenever an upstream hard gate is FAIL/REVIEW_REQUIRED or a claim remains FAIL/REVIEW_REQUIRED. `hybrid_decision()` short-circuits semantic execution on source/factual/policy FAIL.

A `signal_from_factual_finding()` adapter composes the accepted W002 factual findings into claim-level decisions without changing the factual package.

### 3.4 Pluggable semantic sensor + ablation

Added a provider-neutral `SemanticAdapter` protocol and `run_semantic_ablation()`.

The harness executes the same claims/evidence/hard gates with semantic disabled vs enabled and persists:

- backend ID/version supplied by the candidate adapter;
- both complete versioned decisions;
- claim IDs whose support/decision changed;
- `hard_gate_invariant`, proving semantic enablement did not alter hard-fail codes.

There is deliberately no default/final semantic backend in this task. Backend adoption remains evidence-driven on development gold.

## 7. Findings / evidence

### F-001 — Evidence lineage should be validated before interpreting retrieval outcome

A zero-result retrieval is only a meaningful `RETRIEVAL_MISS` if the claim's expected evidence pointers are themselves canonical and resolvable. Otherwise the system would confuse invalid lineage with retriever failure.

### F-002 — Support status and uncertainty cause are separate dimensions

`UNVERIFIABLE` is the support state; retrieval miss and extraction ambiguity are causes with different repair routes. Keeping both dimensions prevents false certainty and enables targeted repair in W003-T006.

### F-003 — Hard-gate precedence belongs in the persisted decision contract

Enforcing precedence only in orchestration code is insufficient. `HybridDecision` itself rejects compensated PASS states, making the invariant durable across future orchestration/framework changes.

### F-004 — Semantic value is measurable without granting semantic authority

The ablation harness can measure whether a candidate backend converts otherwise-unverifiable claims into supported/contradicted/unsupported information while hard-gate codes remain invariant. This supports W003-T008 calibration without pre-selecting a backend.
