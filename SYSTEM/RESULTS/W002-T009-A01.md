## 3. Implementation

### 3.1 Removed semantic enum duplication

T004's independent `FormatKind` no longer defines a second format enum. It is now a compatibility alias of the canonical domain `OutputFormat`.

The generation package no longer defines a second `AudienceLevel`; it imports/re-exports the canonical domain enum.

Result: audience and format have one semantic source of truth while existing T004 import names remain usable.

### 3.2 Reconciled format-unit provenance with the domain core

`SourceRef` remains the format-unit hook that carries `anchor_id`/optional `claim_id`, but its source locator is now the canonical domain `ProvenanceRef` rather than a duplicate flat `{source_id, span_id, page}` shape.

The structured decoder validates nested provenance through `ProvenanceRef.model_validate(...)`, so article paragraphs, carousel slides and video segments inherit the domain invariants for source hash, page and resolvable span/table-cell lineage.

Convenience properties (`source_id`, `source_hash`, `span_id`, `page`) expose canonical provenance without duplicating storage.

### 3.3 Preserved native media contracts

The integration retains the T004 hard structural invariants:

- Article: title, lead/summary, section hierarchy, paragraph-level source refs and closing/takeaways;
- Carousel: contiguous slides with `HOOK -> BODY+ -> CONCLUSION`;
- ShortVideo: explicit timecodes, hook first, required visual cues, monotonic/non-overlapping segments, timeline `<=60s`, estimated spoken duration `<=60s`;
- strict discriminator/allowed-key validation prevents article/carousel/video masquerading.

### 3.4 Integrated generation requests around canonical `VariantSpec`

`GenerationRequest` now wraps the canonical T001 `VariantSpec` plus an independent `AudienceContract`.

It exposes request convenience properties from the `VariantSpec` and rejects audience-contract mismatch. Provider/model fields remain absent from both request and domain spec; provider/model selection stays an adapter/config concern.

### 3.5 Added deterministic 3×3 planner

Implemented `build_3x3_variant_specs(...)` producing exactly nine canonical `VariantSpec`s in stable order:

`BEGINNER | INTERMEDIATE | ADVANCED × ARTICLE | CAROUSEL | SHORT_VIDEO`.

Each `job_id` is deterministic from the source identity/hash plus audience, format, prompt version, output-schema version, factual-backbone ref and policy-context ref. Changing a material planning input changes the generated job IDs.

The planner asserts that the result is exactly nine unique jobs.

### F-001 — T004 duplication was removable without weakening native-format invariants

The independent T004 enums and flat provenance shape were integration seams, not required semantics. Reusing T001 types preserves all format hard gates while eliminating competing domain truth.
