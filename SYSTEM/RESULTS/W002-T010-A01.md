## 7. Provisional architecture posture

### 7.1 Lock now — evidence-backed invariants

Lock these semantics unless future evidence falsifies them:

- typed Python core;
- Pydantic v2 for persisted/domain boundaries;
- one canonical source/provenance spine;
- one immutable factual backbone per source version before nine narratives;
- source-trust gate before generation;
- table facts require semantic table-role provenance;
- exactly 3 audiences × 3 native format specs per valid run;
- audience and format remain independent dimensions;
- hard source/factual/policy findings are non-compensatory;
- `REVIEW_REQUIRED` is a first-class terminal/route state, not a soft PASS;
- branch identity is immutable and joins are keyed by `job_id` without silent overwrite;
- repair is local to the failed branch and diagnostic-driven;
- semantic/LLM judges are secondary sensors and cannot override deterministic hard gates;
- provider/model/parser/framework identity remain outside stable domain truth.

### 7.2 Provisional leader — plain async + explicit typed state/checkpoint abstraction

Use plain async as the implementation leader for the next integration wave because it is the only orchestration candidate with runtime proof for the required proof-case semantics.

Important caveat: the briefing requires a workflow based on graph + state. If plain async remains final, the product must expose an explicit graph/state representation (typed nodes/edges/state machine and inspectable transitions), not disguise a sequential script as compliance with REQ-002.

### 7.3 LangGraph — PENDING_RUNTIME_RECHECK, not rejected

LangGraph remains a challenger, not the selected framework.

Promote it only if the unchanged EXP-B challenger runs and proves:

1. 9-way fan-out;
2. lossless keyed reducer merge;
3. branch-local repair;
4. checkpoint/resume;
5. state history;
6. no substantial framework-specific workaround burden;
7. reducer hazard tests explicitly prevent silent branch loss.

Until then, selecting it would be preference rather than evidence.

### 7.4 Parser posture — contract lock, implementation unlock

Do not lock a parser library yet.

A parser candidate is acceptable only if it:

- preserves critical anchors/caveats;
- exposes stable source/span/table provenance;
- preserves/reconstructs table roles;
- records raw SHA-256 when bytes are available;
- surfaces ambiguity explicitly;
- behaves deterministically on identical bytes or records the reason it cannot;
- routes unsafe fallback to review rather than silently promoting it.

Before final parser lock: expanded raw-byte corpus, multiple table layouts, at least two viable PDF extraction stacks, and scanned/OCR cases if they enter target scope.

## 13. Provider/model / semantic backend decision rule

No candidate receives a lock from popularity, familiarity or framework affinity.

Evaluate on frozen development cases with the same contracts, prompts/schema versions and hard gates. Selection order:
