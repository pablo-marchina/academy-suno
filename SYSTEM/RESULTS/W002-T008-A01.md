## 3. Implementation

Integrated the B04 policy engine with the accepted T001 domain/provenance core while preserving the T003 policy behavior.

### Canonical contracts instead of duplicate types

Removed the policy package's duplicate `SourceType` and duplicate decision enum boundary.

The policy layer now consumes canonical domain types directly:

- `SourceArtifact` is the source-of-truth carrier for `source_type`, `content_type`, `business_context`, `public_source_verified`, source identity/hash and raw artifact reference;
- `SourceProvenance` is derived from the canonical `SourceArtifact` and remains available from both `PolicyContext` and `PolicyResult`;
- canonical `SourceType`, `ContentType` and `BusinessContext` enums replace the local policy source taxonomy;
- `PolicyDecision` aliases canonical `EvalStatus`, so `PASS | REVIEW_REQUIRED | FAIL` has one representation across policy and evaluator layers.

`PolicyContext`, `PolicySignals`, `PolicyRequest`, `PolicyFinding` and `PolicyResult` are now strict immutable `DomainModel` contracts. They therefore inherit deterministic serialization/hashing and `extra=forbid` behavior from T001.

### Auditability/version spine

`PolicyContext` now requires an explicit `policy_version`. `PolicyResult` persists:

- the terminal canonical decision;
- ordered findings/codes;
- disclaimer detection metadata;
- resolved recommendation provenance;
- `policy_version`;
- the canonical `SourceArtifact`, from which source metadata and provenance are reproducible.

This makes source type, content type, business context, source verification, policy version, provenance and review status auditable without duplicating domain contracts.

### Non-compensatory semantics preserved

The decision precedence remains exactly:

```text
any HARD_FAIL finding -> FAIL
else any REVIEW_REQUIRED finding -> REVIEW_REQUIRED
else -> PASS
```

The following remain non-compensatory hard failures when signaled/detected:

- unsupported/new recommendation;
- personalization;
- material grounding mismatch;
- modality escalation;
- attribution loss / recommendation laundering;
- unverified public source;
- fabricated internal policy/disclaimer/regulatory endorsement;
- risky output with unresolved source/business context;
- normative distortion;
- caveat elision;
- source mixing without claim-level provenance.

A disclaimer remains audit metadata only and never changes the decision.

### HF-11 decision

`HF-11` remains a dedicated code for untraceable source mixing rather than an alias. This is the least lossy representation because source mixing is independently observable in the T003 adversarial contract; its semantics remain an unconditional hard fail.

### Internal Suno policy boundary

Internal Suno policy remains `UNKNOWN/configurable`:

- `configured_disclaimer_id` remains optional configuration;
- no default disclaimer, approval workflow or legal/compliance policy is synthesized;
- safe educational content can remain `PASS` with `BusinessContext.UNKNOWN` when no risky output is present;
- risky recommendation-like output with unresolved canonical source/business context triggers `HF-08`.

Risk semantics that are not encoded by the coarser source enum remain explicit policy flags (`source_has_recommendation`, `source_has_forward_looking`, `source_has_legal_normative_effect`) rather than being hidden in a duplicate type system.

The T003 decision function does not require a parallel source taxonomy. Canonical source/content/business dimensions plus explicit policy risk flags preserve the accepted behavior while removing duplicate type ownership.

### F-002 — Review status should reuse `EvalStatus`

Using the canonical evaluator status avoids a second `PASS | REVIEW_REQUIRED | FAIL` enum and makes the policy result directly composable into later hard-gate/evaluation reporting.
