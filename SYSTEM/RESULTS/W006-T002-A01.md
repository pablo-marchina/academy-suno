## 2. Objective outcome

Implemented a vendor-neutral, fail-closed identity/tenancy/session/SSE security substrate under `src/suno_content/security/` and a deterministic adversarial suite under `tests/integration/foundation/`.

The implementation provides:

- stable external `(issuer, subject)` → internal `user_id` principal mapping with remap rejection;
- server-authoritative workspace resolution from application-owned memberships rather than request/token tenant claims;
- deny-by-default role/action authorization;
- explicit tenant enforcement across API, data, object, event and trace surfaces;
- required tenant/provenance identity for protected resources;
- same-origin browser credential topology using a host-only Secure/HttpOnly/SameSite session cookie, CSRF header for mutating API requests, and no browser bearer/session credential in URLs;
- SSE connect/resume with current session + membership revalidation;
- opaque replay cursors bound server-side to authorized stream + session/membership epochs, preventing cursor-only tenant selection;
- session expiry/revocation and membership revocation fail-closed behavior;
- organization/workspace switching that increments session epoch and invalidates stale contexts/prior-tenant replay authority;
- separated runtime/migrator/worker/backup service identities with explicit least-privilege capability sets;
- default-deny telemetry attribute filtering and product-event credential/canary redaction.

The in-process directory/cursor vault is explicitly a portable reference/security harness, not production persistence authority.

## 3. Browser API/SSE credential topology

T002 selects the browser credential **topology**, not an IdP/session-store vendor:

1. same-origin browser route;
2. host-only Secure + HttpOnly + SameSite=Lax session cookie;
3. mutating API calls require a separate session-bound CSRF header;
4. SSE uses GET with the same cookie;
5. resume position uses opaque `Last-Event-ID` only;
6. query-string credentials and browser `Authorization` bearer credentials are rejected by this topology;
7. credentials are never encoded in the replay cursor.

The concrete IdP, session storage and framework adapter remain evidence-gated.
