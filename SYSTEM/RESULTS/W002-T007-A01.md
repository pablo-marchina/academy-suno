### 3.2 Factual backbone / anchor ledger

Added immutable `FactualBackbone` and `anchor_ledger()` plus `build_factual_backbone()` validation.

The builder:

- validates that every anchor provenance points to the same source identity/hash as the parsed document;
- rejects unresolvable span/table-cell provenance;
- preserves T002 source-trust state from parsed-document metadata;
- blocks auto-ready for LOW-trust material/critical anchors;
- requires semantic table-role context before a table-derived hard anchor can be source-ready;
- escalates missing table semantic context to `REVIEW_REQUIRED`;
- escalates a known row/column role contradiction to `FAIL`.

`TableRoleContext` deliberately layers semantic table binding on the canonical `ProvenanceRef`: row role, column role, unit and period-or-metric are mandatory, while the canonical locator continues to own table/row/column/source identity.

### 3.3 Deterministic normalization/checks

Implemented deterministic normalization/checks for the required B03 anchor families:

- number / percentage and pt-BR decimal normalization;
- monetary scale words;
- exact date + quarter/semester/year periods;
- entity/action role swap;
- direction;
- negation;
- modality/condition/range promotion;
- attribution;
- table role;
- explicit allowed rounding control.

The numeric scanner was hardened so a 4-digit year cannot be silently parsed as a partial 3-digit numeric anchor.

### 3.4 Support-state distinctions

The deterministic case evaluator keeps these states distinct:

- source extraction ambiguity → `FACT_SOURCE_EXTRACTION_AMBIGUOUS`, `REVIEW_REQUIRED`, `UNVERIFIABLE`;
- retrieval miss → `FACT_RETRIEVAL_MISS_REVIEW`, `REVIEW_REQUIRED`, `UNVERIFIABLE`;
- confirmed unsupported causality → `FACT_UNSUPPORTED_CAUSAL_CLAIM`, `FAIL`, `UNSUPPORTED`.

This prevents a retriever/extraction failure from being mislabeled as a confirmed unsupported claim.

### 3.5 Semantic-judge independence

`evaluate_case()` uses deterministic source text/table/extraction/retrieval inputs. It does not consult oracle `expected` labels when deciding a result and has no LLM/NLI/network dependency. Semantic agreement therefore has no path to override a deterministic CRITICAL mismatch.

## 7. Findings / evidence

### F-001 — Canonical provenance is sufficient; semantic table roles belong in a composed layer

T001's `ProvenanceRef` already provides stable source/table/row/column identity. B03 does not need another locator schema. What was missing for financial hard facts was mandatory semantic binding of row, column, unit and period-or-metric before source readiness.

### F-002 — Source-trust is upstream authority for hard anchors

A deterministic factual checker cannot repair an ambiguous source extraction by inference. T002 `REVIEW_REQUIRED`/`FAIL` state is preserved, and LOW-trust material anchors cannot auto-PASS.

### F-003 — Known CRITICAL corruption can be blocked without a semantic model

The complete `factual-v001` CRITICAL set is detected deterministically. Semantic verification may later add support/recall, but is not required to veto these known anchor corruptions.

### F-004 — Uncertainty classes must remain operationally distinct

Extraction ambiguity, retrieval miss and confirmed unsupported novelty have different repair routes. Collapsing them into one `UNSUPPORTED` state would create false certainty and poorer repair behavior.

### F-005 — Positive controls matter

The explicit half-up rounding control passes, preventing the deterministic layer from degenerating into brittle exact-string equality.
