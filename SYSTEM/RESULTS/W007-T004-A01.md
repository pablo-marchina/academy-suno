## Table-role hard gate

For Petrobras table 1/page 5, the gold row/column/value assertions were:

- `Receita de vendas` × `2T26` = `169.530`
- `Lucro líquido - Acionistas Petrobras` × `2T26` = `52.445`
- `EBITDA ajustado` × `2T26` = `93.843`

`pymupdf-tables` was the only exercised candidate that passed this hard gate: table-role recall `1.00`, precision `1.00`, and `141` cell-level anchors on the target table. The source geometry split each logical row across adjacent physical extraction rows; the corrected scorer still required the named header, exact row label and exact value within a bounded adjacent-row span.

`pdfplumber-tables` emitted `125` cell anchors but did not preserve the required row labels in its table matrix. Text-only and Tesseract paths did not emit table cells, so they could not pass the non-compensatory role gate.

Therefore `pymupdf-tables` is the **diagnostic** quality/latency point-Pareto member for this bounded table slice. This is not a production winner declaration.

## Real ingestion-contract finding

The current production `PdfExtraction` contract carries flat text, confidence, warnings and table-role ambiguity; it does not carry table/cell provenance. The existing controlled ingestion path fail-closes scan/no-text to OCR and table-role ambiguity to review, and does not promote ambiguous table evidence to trusted `SOURCE_READY`.

The benchmark exposed a concrete integration blocker: PyMuPDF can preserve the tested cell relations, but there is currently no production adapter payload that transports those table/cell relations through the real trusted-ingestion contract. This attempt did not bypass that contract.
