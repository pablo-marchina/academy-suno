## 3. Objective and implementation

B10 is implemented as a provider-neutral telemetry layer around the current orchestration contract, without modifying orchestration or RunStore ownership outside this dispatch.

### 3.1 Versioned event model and lineage

`src/suno_content/telemetry/models.py` defines `telemetry.event.v1` events linked to:

- `run_id`;
- optional `job_id`;
- `operation_attempt` for each stage/job operation attempt;
- deterministic event `sequence` / `event_id`;
- `parent_event_id` linking stage completion/failure to its start and transport retry to the prior failed attempt;
- wall-clock `observed_at` plus monotonic timing coordinates;
- optional provider-neutral usage and priced cost observations.

`JsonlTelemetrySink` writes append-only JSONL, while `InMemoryTelemetrySink` supports deterministic tests and embedding.

### 3.2 Reproducible stage latency

`TelemetryRecorder.invoke(...)` measures each stage with an injectable monotonic nanosecond clock. Completed and failed attempts persist `duration_ns`.

`telemetry.summary.v1` aggregation reports per-stage:

- count;
- min/max;
- integer mean;
- deterministic nearest-rank p50;
- deterministic nearest-rank p95.

Clock injection makes timing behavior reproducible in tests instead of coupling acceptance to machine wall time.

### 3.3 Transport retry is not quality repair

The telemetry taxonomy has distinct `transport_retry` and `quality_repair` event kinds and distinct aggregates.

Transport retry evidence is created only when a subsequent operation attempt follows a configured transport exception, and it references the failed attempt through lineage. Quality repair is emitted only through the repair callback wrapper and carries its independent `quality_repair_attempt`.

This mirrors W003-T003's already-distinct runtime control loops without conflating them in observability.

### 3.4 Usage/cost remain N/A unless observed

Usage is adapter-supplied through optional `UsageExtractor` hooks. If no extractor/observation exists, event usage and aggregate usage are `null` (N/A), not zero.

`UsageObservation.complete` is explicit. `PricingTable` is versioned and only produces a cost when:

1. usage was actually observed;
2. the observation is marked complete; and
3. every observed meter has a price in the supplied versioned table.

Otherwise cost stays `null` (N/A). No provider price is embedded in production telemetry code.

The experiment uses **synthetic demo pricing only** (`demo-pricing.v1`) to prove the mechanism; it is not a claim about any provider's real price.

### 3.5 Hard failures/review states remain visible

`observe_run_state(...)` emits run and branch state observations preserving:

- run phase;
- branch phase;
- branch error;
- quality-repair count;
- transport-retry counters.

Aggregation explicitly retains `failed_job_ids`, `review_required_job_ids` and the complete latest branch-state mapping. A failure or human-review state therefore cannot disappear inside averages or success-only metrics.

### 3.6 Provider-neutral hooks

`OrchestrationTelemetryHooks` wraps the current framework-neutral callbacks:

- planner;
- generator;
- evaluator;
- repairer;
- aggregator.

No provider SDK, model vendor or orchestration framework type is required. Provider-specific usage schemas are normalized only at an adapter-provided `UsageExtractor` boundary.

## 5. Findings / evidence

### F-001 — audit telemetry can remain orchestration/provider neutral

The existing W003-T003 callback boundary is sufficient to instrument stage attempts without changing its graph/runtime or binding observability to a provider SDK.

### F-002 — retry/repair semantics remain independently measurable

Distinct event kinds, counters and lineage make transport recovery and content-quality repair separately auditable rather than two names for a generic “retry”.

### F-003 — absent commercial evidence can stay absent

Explicit `None/null` usage and cost plus a completeness flag avoid the common failure mode of converting unobserved tokens/usage into zeros or estimated cost presented as observed fact.

### F-004 — pricing provenance is part of cost evidence

Every produced cost carries a `pricing_version`; incomplete usage or an unpriced meter suppresses cost rather than silently applying a partial table.

### F-005 — terminal failures survive aggregation

The summary is not success-biased: branch-level `failed` / `review_required` states and errors are first-class fields even when latency/usage distributions are also present.

## 8. Assumptions / risks affected

### Usage normalization

Provider adapters still need to supply trustworthy `UsageObservation` mappings. The telemetry layer intentionally cannot infer missing provider usage from output text or generic heuristics.

### Pricing data

A real deployment must inject a separately governed, versioned pricing table whose provenance/date/provider applicability are validated outside this generic package. The committed demo pricing is synthetic only.

### Cost meaning

`observed_cost` means cost computable from the observed complete usage meters and supplied pricing version. It is not an estimate of all-in infrastructure cost, labor cost, taxes, discounts, cache effects or unobserved provider charges.

### Sink durability

Append-only JSONL is a proof/audit sink, not a final production telemetry-backend decision. Production concurrency, retention, indexing, redaction and delivery guarantees remain deployment decisions.

### Orchestration integration

Because this worker respected ownership boundaries, W003-T003's engine was not modified to install telemetry automatically. The orchestrator or composition layer must pass wrapped callbacks and call `observe_state(...)` at desired state checkpoints when integrating B10.
